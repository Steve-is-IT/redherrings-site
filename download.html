Release notes

What changed in each version. Every release keeps the full case library generating and verifying.

v1.6.0 October 3, 2026 · release

Beginner incident-response on-ramp, instructor IOC export, and the license-server admin console — plus the packaging work to ship signed Windows builds. Every scenario still generates and verifies (full suite green).

Scenarios

  • Three new easy First Look incident-response cases, each re-derived from the planted artifact: Reading a CloudTrail Log (follow an AWS account-takeover chain — console login → backdoor IAM user → access key → S3 pull), One Beacon in the Web Traffic (proxy/egress triage: rule out normal browsing, find the one beaconing destination and its upload), and A Burst of Failed Logons (a credential brute force in an Entra sign-in log, with the user's normal sign-in as a baseline).
  • The two SOC-queue First Look cases now have distinct codenames (the EDR case is "Tripwire", no longer a duplicate "The Queue"), and a new test_unique_titles gate enforces unique id, name and codename across every built-in scenario.

Instructor tools

  • IR labs now export indicators of compromise in the instructor package: iocs/<student>.csv, iocs/<student>.stix.json (STIX 2.1 bundle with indicator + attack-pattern + report), and a combined iocs-all.csv. Indicators (hashes, IPs, domains, URLs, emails) and ATT&CK techniques are pulled from the built lab's answer key; STIX ids are derived deterministically from the case id and value, so the same seed reproduces the same bundle. No-op for digital-forensics cases.

License server

  • New browser admin console at /admin on top of the existing admin API: overview metrics, issue/revoke/reveal licenses, seat release, Stripe membership status, and signed revocations.json download. Password sign-in (PBKDF2) with an HMAC-signed HttpOnly SameSite=Strict session cookie and CSRF-protected mutations; the bearer-token API and CLI are unchanged.

Packaging & billing

  • One-shot signed Windows release script plus a launch-night checklist.
  • Stripe Educator tier description corrected to 40 students per lab, matching the tier and the site.
v1.5.0 October 2, 2026 · release

A library-wide artifact-realism pass so every planted artifact looks and behaves like the real one and students build genuine, transferable tool skills. Six parallel DFIR audits (one per artifact family) graded each generator against how the real tool/OS/format behaves; this release implements the findings. Every scenario still generates and verifies (full suite green).

Cloud (CloudTrail / M365 / Entra)

  • IAM/STS CloudTrail events are recorded in us-east-1 (global services), regional events share one account region, and the region is verified.
  • M365 unified-audit RecordType is set per operation (ExchangeAdmin, SharePointFileOperation, AzureActiveDirectory, …), not a constant 15.
  • userIdentity carries accessKeyId so the CreateAccessKey → data-exfil chain is reconstructable; ConsoleLogin shows a browser user-agent; clientAppUsed is normalized to the Entra enum.

Network / PCAP

  • Realistic TCP/IP fingerprint: modern SYN options (MSS, SACK, timestamps, window scaling), scaled windows, per-packet IP id, and TTL decremented for remote servers so local vs. remote is readable.
  • FTP uploads use real passive FTP — USER/PASS/PASV/STOR on the control channel and the file on a separate data channel to the PASV-advertised port, never on 21 (new question teaches parsing the 227 reply).
  • HTTP exfil is a real POST whose body is the staged archive, so wire byte-count and SHA-256 equal the file carved from disk (new disk↔wire correlation question).

Memory (Volatility-style)

  • System DLL base addresses sit in the canonical high range with shared per-image bases and realistic sizes (no more impossible wrapped addresses); pstree roots render without a leading asterisk and every process is listed; malfind shows the real Hexdump/Disasm columns; svchost-hosted processes descend from svchost.

Windows Event Log

  • 4688 SubjectLogonId correlates to the 4624 TargetLogonId of the session that spawned it (the logon→process pivot); 4625 fields vary by logon type; optional Kerberos type-3 auth; 7036 Binary encodes the service name; richer CurrentVersion for OS fingerprinting.

Linux / macOS

  • auth.log carries the matching pam_unix session/auth and systemd-logind lines (PID-correlated), useradd logs its private group (UID==GID), and SSH noise no longer logs service/nologin accounts.
  • macOS log-show timestamps are microsecond-precise; LSQuarantine web downloads use type 0 and record the downloading app's bundle id.

Email / mobile

  • A dkim=pass message now carries a real DKIM-Signature.
  • Mobile phone numbers are valid NANP (owner and noise), the location store drops the fabricated place-name label for a real Android cache keyed on coordinates and provider, and WhatsApp key_id is an opaque random token.
  • New iOS iPhone family: set platform: ios on the mobile artifact to plant a real sms.db (the message / handle / chat / chat_message_join join) and an AddressBook.sqlitedb under the iOS /private/var/mobile tree. message.date uses Apple Cocoa time (nanoseconds since 2001-01-01 UTC), so students practise the decode that trips up anyone who reads it as Unix time. New case mobile-ios-imessage ("The iPhone in the Evidence Bag").

EDR / SIEM

  • EDR/SIEM feeds have sub-second timestamps and an unambiguous first detection.
  • EDR detections now serialize to fully per-vendor record schemas — CrowdStrike Falcon (DetectId, SeverityName, SHA256HashData, aid), Microsoft Defender (alertId, mitreTechniques, evidence[], machineId) and SentinelOne (threatInfo, agentRealtimeInfo) — chosen by the feed's schema. SIEM exports do the same per platform: Splunk ES notable events (annotations.mitre_attack, dest_nt_host) and Microsoft Sentinel alerts (SystemAlertId, Techniques, Entities[]). Facts stay vendor-neutral: the verifier normalizes each vendor's shape back and re-derives every answer, so existing scenarios are unaffected.

Windows Prefetch

  • Version 30 Prefetch files are now MAM (Xpress-Huffman) compressed on disk like a real Windows 10/11 artifact (a raw file/xxd shows MAM\x04); version 23 (Windows 7) stays uncompressed SCCA, which is also accurate. New formats/xpress_huffman.py implements the MS-XCA compressor and MAM wrapper, validated by round-tripping through both an independent size-aware decoder and the third-party dissect.util MS-XCA decoder. The stream is a single chunk with a literal-only parse (both valid MS-XCA); PECmd, WinPrefetchView and libscca decompress it natively, and the bundled windowsprefetch parser is driven through the decompressed body. Bodies over one chunk (> 64 KiB) stay uncompressed. Full back-reference compression and multi-chunk streams remain a future enhancement (they need round-tripping against PECmd on Windows).

All of the above follow the invariants in docs/FORENSIC-REALISM.md.

v1.4.0 October 2, 2026 · release

Library, teaching and authoring upgrades on top of v1.3.0, a library-wide forensic-accuracy pass, a new instructor-controlled question-count, and accessibility and CI hardening.

Cases (library -> 63)

  • A new "Spared No Expense" marquee: a 26-question, 9-artifact-family insider sabotage capstone (a bribed admin kills the cameras and logging, exfiltrates the stolen datasets, and blames a storm), threading one indicator across memory, packet capture and the cloud.
  • An Incident Response on-ramp: four new lower-tier IR cases so the GCIH and CySA+ tracks start gently - *First Look: Reading a SIEM Alert*, *First Look: An Impossible-Travel Sign-In*, *Malware Triage: From Alert to Verdict*, and *Phishing to Foothold*.
  • A depth pass on the thinnest cases (mobile location trail, memory injection, HTTP exfil): each now corroborates across a second and third artifact family with more per-student variance.

Teaching

  • Post-grade learning loop: the solve portal results screen now shows, per question, where to look, how to work it, the tool, the NIST phase and the case's ATT&CK context - the method, never the answer, and withheld during an open exam.

Authoring

  • Exam builder: assemble questions from any cases into one exam. Each question is still built and graded against its own per-student seeded variant, with a combined answer key and a single sectioned worksheet.

Learning pathways

  • Pathways are grouped by discipline (Digital Forensics | Incident Response), with new IR certification tracks for Incident Handling (GCIH) and SOC Analyst & Triage (CompTIA CySA+).

Forensic accuracy (library-wide)

  • Host/OS line now matches the real platform. The student README printed a Windows host for every case, even Linux, macOS, phone and cloud scenarios. Each discipline generator now records the real host (server, workstation, handset or tenant) and the README labels it Host, Device or Environment.
  • Corrected answer keys that were mis-grading. easy-persistence, easy-account-events, easy-timeline, vpn-compromise and the sign-in First Look had questions whose keyed answer did not match what the evidence uniquely supports; all now resolve to the right value.
  • Artifact realism fixes across disciplines: OpenSSH password vs publickey accept lines and fingerprint length, sudo working directories, macOS LaunchAgent labels and shell-history ordering, valid NANP phone numbers, Entra/cloud sign-in logs showing public egress IPs (never internal), and corrected ATT&CK technique mappings and NIST phase tags.
  • Forensic-realism knowledge base (docs/FORENSIC-REALISM.md) captures these invariants for authors, wired into the contributor docs.

Generation & authoring

  • Instructor-controlled question count. Build a shorter, balanced lab by choosing how many questions each student gets, down to the case minimum; every student still receives a different seeded draw. First Look cases stay fixed so they always cover their lesson end to end.
  • Higher per-tier question caps: easy 20, medium 30, hard 40, expert 50, Marquee 50 (First Look 15), replacing the old flat limit — headroom for deeper cases, enforced by validation and the test gate.
  • Incident-response scaffolding on the topical IR cases: every question is tagged with its NIST 800-61 phase, and each case gains a containment or eradication decision question, matching the purpose-built IR cases.
  • Differentiated near-duplicate cloud cases so each teaches a distinct lesson (a legacy-auth MFA bypass read field-by-field vs an MFA-fatigue response decision; shadow-AI data governance vs personal-cloud-drive exfil).

Accessibility

  • A keyboard skip-to-content link, aria-current on the active navigation item, and a stronger reduced-motion mode across the app.

Reliability

  • A CI test gate runs the full suite on every push to main and on pull requests.

## v1.3.0

A second discipline — Incident Response — and a real memory artifact.

Incident Response discipline

  • A new top-level discipline axis (Digital Forensics | Incident Response) alongside the shared difficulty ladder. IR cases are faceted by MITRE ATT&CK tactic instead of certification track; Digital Forensics keeps its platform/cert facets. First Look is now its own difficulty tier.
  • IR cases work from the responder's own tooling with two new evidence generators: an EDR detection feed (edr/detections.json + CSV — process tree, file hashes, ATT&CK technique, severity, sensor action) and a SIEM alert export (siem/alerts.json + CSV — correlated rules, entities, technique, severity). Both re-parse their own output in verification, and hashes are per-student so cohorts differ.
  • Questions gain IR answer types — choice, severity, boolean, ioc (set-graded), mitre (ATT&CK technique, parent-aware) and sequence (ordered, partial credit) — plus a NIST 800-61 phase tag, a diegetic response_clock, and an optional suggested_timer_minutes.
  • A curated ATT&CK tactic/technique catalog and a /api/attack coverage endpoint, mirroring the certification tracks.
  • 15 incident-response cases across the ladder, from *First Look: Reading an EDR Alert* through the *Operation Nightfall* marquee (a double-extortion ransomware incident worked across SIEM, EDR and host logs through every NIST phase).

Real memory artifact

  • The memory evidence now also emits a genuine Windows process minidump (.dmp) alongside the Volatility-style text: a hand-written MINIDUMP with SystemInfo/Thread/Module/Memory64/Comment streams that opens in WinDbg and yields to strings/YARA/PE carving, with the planted secrets recoverable from the dump and verified by re-parsing it.

Case Library

  • Discipline → difficulty → topic filters (dropdowns), discipline-aware case cards (ATT&CK tactic chips for IR), a per-card Generate button, and an equal-height card layout.

## v1.2.3

Easier LMS adoption and two solve-portal refinements.

LTI one-click install

  • Dynamic Registration (/lti/register): an LMS admin installs Red Herrings from a single URL. The tool fetches the platform's openid-configuration, registers itself (private_key_jwt, the LTI scopes, resource-link + deep-linking messages), stores the platform, and signals the LMS to close the window. No hand-entered endpoints or client ids. /lti/config advertises the registration_url. See docs/LTI.md.

Solve portal

  • Release scores: an instructor can reveal exam scores to the whole class after the fact from the results screen; scores stay instructor-only until then.
  • Resume after refresh: a student's typed answers are saved to a per-link local draft and restored on reload, so a mid-exam refresh never loses work.

## v1.2.2

A hardening and content release on top of v1.2.1.

Security & academic integrity

  • The student solve portal's per-question check is now budgeted, and the get/check/submit endpoints are rate-limited per link and per client, so the correct/incorrect response can no longer be scripted to brute-force an answer. Submissions are restricted to the lab's own questions and each answer is length-capped. The LTI launch surface was reviewed (signature, issuer, audience, expiry, one-time nonce and deployment all enforced).

New cases (library -> 54)

  • "Hands on Keyboard" (medium): PsExec-style lateral movement to a file server across the Security and System event logs, the registry and Prefetch - a network logon from an internal host, a remote-execution service, the tool it ran, and a Run key, with no new account to contrast with the rogue-admin case.
  • "Free Electricity" (medium): a public web server pegged by a cryptominer - the Apache access-log entry point, the miner pulled and launched at a pool, a per-minute cron relaunch, and a rogue authorized_keys entry.

## v1.2.1

Instructor and student experience, plus optional LMS integration.

Student solve portal

  • An optional, fully offline in-browser portal: each student gets a private, unguessable link to answer their lab. Practice mode gives instant per-question feedback and optional hints; timed exam mode enforces a server-side countdown, captures and locks answers, flags late submissions, and keeps scores instructor-only until released.
  • The answer key is never sent to the student view - a single answer is graded server-side with the existing tolerance/fuzzy grader and only right/wrong plus a note comes back.
  • Gated behind a new student-portal capability (Educator tier and up). The results screen gains a student-links panel (copy one / copy all / CSV) with live submission status.

Fairer, harder to copy

  • Per-student question shuffle: a seeded, reproducible, prerequisite-aware shuffle of question order across both the printed worksheet and the portal.

Class analytics dashboard

  • Over the portal submissions: class average and median, pass rate, score distribution, a per-question table (hardest first, most common wrong answer, and a flag for any likely mis-keyed question), and a correct-rate breakdown by difficulty. All on the instructor's machine.

LTI 1.3 connected mode (optional)

  • Deployed as a hosted tool, Red Herrings plugs into Canvas, Blackboard, Moodle and D2L with Deep Linking (pick a case inside the LMS), Names & Roles (pull the roster) and Assignment & Grade Services (scores post straight to the gradebook). Implemented on cryptography + httpx with full launch validation (signature, iss/aud/exp/nonce/deployment, one-time state). Off by default; the desktop app stays fully offline. See docs/LTI.md.

## v1.1.1

A major content and workflow release: two new host platforms, flexible question sets, learning pathways, evocative case names, a new Marquee capstone, and a court-ready report deliverable.

New evidence engines & platforms

  • Linux host engine — /var/log/auth.log (SSH, brute force, sudo, useradd), ~/.bash_history, cron and authorized_keys persistence, and Apache/nginx access logs — all plain-text, verified by re-reading the files. Three cases and a Linux Forensics track.
  • macOS host engine — unified-log export, LaunchAgent/LaunchDaemon plists, the LSQuarantine database (download provenance), Safari History.db, and ~/.zsh_history. Three cases and a macOS Forensics track.
  • Cloud & SaaS track plus a Microsoft 365 account-takeover case (sign-in logs + Unified Audit Log).
  • Mobile call detail records (calllog.db) and a harassment case; memory gains ldrmodules and a code-injection case.

Marquee capstones

  • New Marquee category: rare, full-arc cases that run the whole skill range in one connected story and carry their own tag.
  • First Marquee: "Nakatomi Plaza" — a 24-question, Die-Hard-themed intrusion across email, browser, event logs, memory, cloud and disk, where the account found early is the account that opens the vault and the C2 address is the exfil address.

Flexible, fairer question sets

  • Instructor-selectable question count per student (slider, capped per licence tier), drawn as a naturally balanced spread across every artifact and seeded per student — reproducible for replay and different between students.
  • Minimum of 10 questions on every case; counts shown as min–max ranges so no single answer is an outsized share of the grade.
  • Case durations recalibrated to a real difficulty curve, and question pools deepened with varied question types (correlation, timeline, provenance).

Learning pathways

  • Ordered, case-by-case curricula (certification-prep and role paths), with a new in-app Pathways view and a public Pathways page.

Case names

  • Optional codenames (Rabbit Hole, Ghost in the RAM, Paper Trail, Reply All, …) shown as the headline with the descriptive name as a subtitle; expert names cleaned up.

New deliverable

  • Investigation Report & Chain of Custody template (PDF + DOCX): the evidence manifest and SHA-256 hashes are pre-filled from the student's own evidence, followed by a custody transfer log, executive summary, a finding-per-question write-up, timeline, IOCs, conclusions and an examiner certification block. Opt-in per generation.

Website

  • Generated case catalog, Pathways page, and Certification / Cloud / Linux / macOS marketing; homepage polish; de-cluttered the LMS strip; pricing defaults to Individuals.
