GCFR practice labs, one tenant at a time

The GCFR objectives expect a responder who can investigate identity and cloud audit logs without a disk image: anomalous sign-ins and legacy authentication, MFA-fatigue takeovers, hidden mailbox rules and role abuse in Microsoft 365, leaked service-account keys and tokens across a project, and data pulled from the cloud by an account that should not have had it.

This pathway starts with a single cloud sign-in log and adds one identity or platform at a time: MFA fatigue, Exchange inbox rules, a full M365 takeover, a leaked GCP key, a cryptojacking pod in Kubernetes and personal cloud exfiltration. The capstone is a stolen access key used across a tenant, which has to be traced through every log the provider writes.

Who it is for

  • Candidates preparing for the GCFR who want to work real audit-log exports in JSON and CSV, not console screenshots.
  • Instructors adding cloud to an IR course who need labs that need no cloud account to solve.
  • Enterprise responders whose incidents now start in the identity provider and who want structured practice before the next one.

What you get with every case

  • A different variant per student. Same case, same rubric, different names, hashes, timestamps and answers, so students can talk about method without sharing answers.
  • Evidence in the real on-disk format. Registry hives, EVTX, PCAP, SQLite, JSON audit logs and memory images open in the tools the exam expects.
  • A verified answer key. Every answer is re-derived from the planted evidence before the lab ships, so grading disputes end at the artifact.
  • One-click grading and LMS export. Canvas, Blackboard, Moodle, D2L and LTI 1.3 grade passback, or a CSV. See the student portal.
  • Runs on the instructor's machine. Windows installer plus macOS and Linux, fully offline after activation. Nothing to host and no student data leaves the room. Course packs on courses.
